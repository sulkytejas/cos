Ayumi's Memory

How Ayumi learns things, remembers them, and uses them to write the Today page. Build plan + living progress tracker.
locked: 2026-06-06 last updated: 2026-06-06 status: ALL PHASES BUILT — slices A·B·C·P·D done; rehearsal passed schema rev: drizzle 0013

0 · The idea we locked decided across two sessions, checked against how the big products do it

Ayumi keeps a notebook. Every entry is one small note: what Ayumi learned, who it's about, which emails or meetings prove it, and — if it later turns out wrong — the date it stopped being true. The notebook is a normal database table. No graph database, no AI search index. We checked how ChatGPT, Gemini and Claude do memory (June 2026): all three work this same simple way — a background job reads past activity, writes short notes, builds a one-page summary, and pastes that summary into every new conversation. None of them use a graph.

The rule that makes this safe: save rich data now, build fancy machinery only when something needs it. If a future feature ever asks a question Ayumi can't answer by just reading the notes — like "trace how this relationship changed over six months, across ten people" — that's the day we build the graph engine. The notes are exactly the raw material it would be built from, so nothing we do now gets thrown away.

1 · Three new pieces all follow the house rules every table already uses: uuid id · userId · created/updated · soft delete

people

Contact cards

  • canonicalName · "Karan Mohla"
  • handles · every email address and nickname that means this person
  • role, org · "Partner, Sequoia India"
  • firstSeenAt / lastSeenAt · when he first and last showed up
  • mergedIntoId · two cards turn out to be one person? point one at the other — don't delete
Right now "Karan" is just text inside email rows. After this he's a real card that notes, briefs and lookups can all point at.
observations

Ayumi's notebook — one note per row

  • body · the note itself, in plain words: "Karan usually runs 10 minutes late"
  • about · who or what it concerns. A note about two people IS the connection between them
  • kind · fact / preference / pattern / relationship / state
  • confidence + source · saw it happen, was told, or guessed
  • receipts · the actual emails and events that back it up
  • firstSeenAt / lastSeenAt / weight · how often life keeps confirming it
  • invalidatedAt · the date it stopped being true
  • supersededById · points at the newer note that replaced it
  • struckAt · you crossed it out — forget it
Old notes are never deleted, only end-dated. That avoids ChatGPT's famous bug where a cancelled trip keeps coming back forever. And every note can prove itself — that's the receipts.
digests

Ayumi's cheat sheet — one page per user

  • body · short markdown, about half a page
  • sections: people · habits · preferences · what's going on right now
  • every line shows how many receipts back it · "Karan runs late, as a rule (×4)"
  • rewritten every night from the strongest notes
  • pasted into every single thing Ayumi writes
Same trick ChatGPT and Gemini use: don't search memory — keep one short summary and always have it in hand.

4 · Decisions we made written down so we never argue them twice

DecisionWhy
Plain table, no graph engineA graph engine means weeks spent on "is this Karan the same Karan?" and forcing every note into fixed categories. The notes don't fit fixed categories — that was the founding rule. We revisit only when a feature needs a question Ayumi can't answer by reading the notes.
No AI search index in v1ChatGPT and Gemini ship memory with no search index at all — one short summary in the prompt won the argument industry-wide. We add search only if we catch Ayumi missing notes that should have been found.
Cheat sheet is always onGemini only uses its memory when you say "personalize this." A chief of staff who waits to be asked isn't one.
Every note must have receiptsMost products can't tell you why the AI believes something. Ours can, note by note. The red pen also needs receipts to know exactly what to strike.
End-date, never deleteDeleting loses the story and invites ChatGPT's cancelled-trip-keeps-returning bug. An end date keeps history honest: "that was true until April."
Night work rides the 6am jobThe expensive thinking happens while you sleep, in a job slot that already exists. Zero felt latency.
Side table for fast lookups"All notes about Karan" must be instant. A two-column helper table keeps it instant — still just data.
Person matching stays dumbExact email match only; anything fuzzy becomes a suggestion for you. A wrong merge makes Ayumi confidently wrong about a person — the single worst failure a chief of staff can have.
